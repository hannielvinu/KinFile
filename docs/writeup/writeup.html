2. Starting point

From scratch. No upstream editor project (Cline, Continue, Roo Code or opencode) was forked, so there is no fork commit to declare. All editor code is our own and is in the repository's history from the first commit. Bundled dependencies: @modelcontextprotocol/sdk (MIT), zod (MIT), diff (BSD-3-Clause); listed in THIRD_PARTY_NOTICES.md. Licence: MIT. The agent loop is TrueForge's; the extension never calls a model provider.

3. Architecture on TrueForge

The extension is a TrueForge client over its HTTP API. It creates a session per request from the agent spec in src/core/agentSpec.ts (exported to agent/kinfile.agent.json), posts a turn and renders the SSE events (model.message.delta, tool calls, thread.created, compaction, turn.done). Stop calls POST /sessions/{id}/cancel.

Editor capabilities are MCP tools. The extension runs an MCP server, kinfile-editor, on 127.0.0.1 and registers it in TrueForge: read_file, search_code, related_files, find_symbol, list_files, propose_edit, create_file, run_command. The agent decides what to read and change.

Tool approval drives the diff review. The three write/run tools are in require_approval_for_tools. On tool.approval_required, Kinfile reads the paused call's arguments, stages the proposal in memory and opens the hunk review. The user accepts or rejects each hunk; only accepted hunks are written, as one undoable edit. Kinfile then answers user.tool_approval. An invalid edit (e.g. old_string not found) is denied with the reason, so the model corrects itself.

Why these features. A scout subagent explores (related files, search, symbols) in its own thread and returns a short file list, so the main thread's context holds the plan, not the search noise. Deferred tool loading keeps only four core tools in the prompt; the long tail (run_command, create_file, find_symbol, list_files) is discovered through list_tools/call_tool when needed. Compaction (trigger 60k input tokens) keeps long agent runs inside any model's window.

4. How context is selected

Every request gets an automatic Context Receipt. Each text file in the repository is scored with four repo-agnostic signals:

  • Text: BM25-style term match over contents, plus path-segment match weighted by how rare the term is among paths (so flask, which is in every path, counts for ~0).
  • Symbols: definitions matching the request (regex index for Python/TS/JS/Go/Rust/Java). This brings in the closest existing example to copy, e.g. routes_command.
  • Kin (git co-change): for the top three source files, files that changed in the same commits (last 3,000 commits; renames followed; commits touching more than 40 files ignored). Measured on Flask 3.1.3: src/flask/cli.py changed in 172 commits, with tests/test_cli.py in 52 and docs/cli.rst in 19. These are exactly the test and docs Task B needs, found without the user naming them.
  • Test pairing: test_<name> files for the top source files.

Budget: 16,000 tokens by default, 12,000 in the recorded demo (setting kinfile.contextBudgetTokens). The anchor file is packed first. A file may use at most 25% of the budget (prose 12.5%). Small files go in whole; large ones as a symbol outline plus line windows around the matches. @file and @Symbol mentions are always included. Every chosen file is listed with its reasons and token cost, and left-out files are listed too. Receipt for Task B at a 32k budget (index 0.2 s once, selection about 40 ms); the demo's 12k budget keeps the top five:

31,821 / 32,000 tokens · 7 files from 218 · 2,408 commits indexed 1 src/flask/cli.py 7,409 tok excerpt anchor file; path matches "cli"; defines get_command… 2 tests/test_cli.py 5,943 tok full changed together with cli.py in 52 of its 172 commits; test file for cli.py 3 CHANGES.rst 3,727 tok excerpt changed together with cli.py in 52 of its 172 commits 6 docs/cli.rst 3,647 tok excerpt changed together with cli.py in 19 of its 172 commits

The agent still has its tools for anything else, and related_files gives it the same co-change data on demand.

Switching models: providers live only in TrueForge (npm run setup loads them from a git-ignored config/trueforge.local.json; an example file is committed, keys never). The VS Code setting kinfile.models is the ordered fallback list (empty = every model configured in TrueForge). Nothing in the code names a provider. Relay: a failed turn (provider error, bad key, unreachable endpoint, or no event within 120 s) is retried once after 1.5 s, then rerun on the next model automatically, with a visible notice; a failed model cools down for 5 minutes; fallback only happens before any change was accepted. Token economy: 12k-token context budget in the demo, reasoning effort "low", the scout limited to 3 tool calls, and TrueForge's own silent HTTP retries disabled (MODEL_HTTP_MAX_RETRIES=0) so a slow free endpoint is never paid twice. scripts/model-relay.mjs (local, optional) restores Gemini 3 "thought signatures" that TrueForge's OpenAI-compatible provider drops, and paces free-tier 429/503 responses.

8. Known limitations

  • Co-change needs git history; on a new repository Kinfile falls back to the text, symbol and test signals. Co-change is a strong hint, not proof of a dependency, which is why the receipt shows the counts.
  • The symbol index is regex-based (fast, no native dependencies); it can miss unusual definitions. Edits use exact search/replace with a whitespace-tolerant fallback.
  • If a model fails after some hunks were accepted, Kinfile stops with a clear message instead of switching models mid-change.
  • Code Mode and Skills are unused: they need TrueForge's sandbox, which is optional for the fixed tasks.
  • On free tiers the agent is slow (NVIDIA's free queue took ~1 min per step; Task B took ~20 min of model time, fast-forwarded in the video). Subagents may explore but not edit: Kinfile denies write tools on subagent threads.
  • With another month: tree-sitter symbols and a call graph as a fifth signal; learn signal weights from each repository's own history (replay past commits and measure recall); a "related tests" runner after each accepted hunk; upstream a model-fallback chain and approval-with-edited-arguments to TrueForge itself.
